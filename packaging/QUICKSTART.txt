FHIR cohort synth
================

Extract the entire archive before running it. Keep the executable and _internal
folder together. Python, SQLite and the FHIR R4 definitions are included.
No installation, administrator access or internet connection is needed to run.

Windows x64 (PowerShell)
-----------------------
Open PowerShell in the extracted folder:

  .\fhir-cohort-synth.exe run --input "C:\FHIR export" --output "C:\FHIR output"

Linux x64
---------
Extract with: tar -xzf fhir-cohort-synth-<version>-linux-x64.tar.gz
Open a terminal in the extracted folder:

  ./fhir-cohort-synth run --input "/data/FHIR export" --output "/data/FHIR output"

This Linux build targets glibc 2.35 or newer, such as Ubuntu 22.04 or newer.
It does not target Alpine Linux or ARM processors.
Windows builds target 64-bit Windows 10/11 and Windows Server 2022 or newer.

Try the included invented example
--------------------------------
Windows:
  .\fhir-cohort-synth.exe run --input examples\mii-demo-bundle.json --output example-output
Linux:
  ./fhir-cohort-synth run --input examples/mii-demo-bundle.json --output example-output

The output folder must be new and outside the input folder. For another run,
choose a new name, such as example-output-2. Existing results are never replaced.
Quote paths containing spaces. Inputs may be JSON, NDJSON or JSONL, including gzip.

While it runs
-------------
The terminal shows the current stage, elapsed time and processed counts.
Long stages repeat an update about every 10 seconds. Percentages describe the
current stage. Wait for the final completion message before using the output.
Ctrl+C stops the run. After interruption or failure, retry with a new output path.

Your output
-----------
  intermediates/       Ingestion database, transformation state and run status
  result/fhir/         Perturbed FHIR files, retaining source file organization
  result/reports/      Processing reports

After completion, copy result/ to collect the FHIR export and reports together.
Source Bundle resources are unpacked into NDJSON files.

The defaults are independent signed 1-16% changes to supported quantities,
one date shift of up to 30 days per patient, and replacement identity fields.
Values with missing or unsupported units are preserved along with their units.

Help: use --help or run --help after the executable name.
Version: use --version after the executable name.
Exit codes: 0 completed (possibly with warnings), 2 error, 130 interrupted.
Build information is in build-info.json. Component notices are in licenses/.
